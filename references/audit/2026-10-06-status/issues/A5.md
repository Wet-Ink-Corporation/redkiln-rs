TITLE: Make the per-item token charge fail closed and dispatch admission atomic
LABELS: bug
STATUS: untracked

## Finding
The per-item envelope sums tokens from `dispatch_completed` rows. A row whose `usage` is present but does not deserialize is skipped with `continue`, so it charges 0 and the appetite check fails open. Separately, `dispatch_once_at` reads the journal, admits, and then appends the `dispatch` row in separate steps with no lock held across them, so two writers can both pass the cap.

## Evidence
- crates/rk-kernel/src/workflow/envelope.rs:448 @ ce4ed1a (= 62dd3b8): `let Ok(usage) = serde_json::from_value::<Usage>(..) else { continue; }`. The doc at :431-436 accepts only absent or `null` usage as "charges nothing, bounded by the cap".
- crates/rk-kernel/src/runtime/activity.rs:637-638 @ ce4ed1a: `envelope.admit(&self.journal(item)?, item)?;` then `self.append(dispatch_event(..))`; the store guard is taken per call, not across both.
- Contrast: `commit_at` in the same file holds one guard across read and append (AC-012).
- Records: ADR-0198 decision 4 and s8h section 8h.9 (runbook/phase-1/s8h-cards-and-run-environment.md:1497-1498) specify the read-per-dispatch design. Neither records the malformed-usage case or the check-then-act window.

## Impact
A malformed usage row silently under-counts spend. The race needs two live runtimes on one item. The run lock taken by `worktree::enter` (run.rs ~400) is the only mitigation and it sits outside the envelope.

## Suggested fix
Return an error (or charge a saturating sentinel) when non-null usage fails to deserialize, and add a test row for it. Take the store guard once around `journal` + `admit` + `append`, or append a reservation row inside the admission critical section.
