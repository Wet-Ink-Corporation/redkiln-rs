TITLE: Add rust and python to the rank-tie lint toolchain domain
LABELS: bug
STATUS: untracked

## Finding
The load-time rank-tie lint (`step4::rank_lint`) enumerates a hard-coded toolchain domain of node, unreal, dotnet and node+unreal. It has no rust or python instance, so a rank tie that only exists in a rust or python context is never found at load. The rigor-monotonicity sweep hard-codes the same four, but it runs only from tests.

## Evidence
- crates/rk-kernel/src/select/step4.rs:595-600 @ ce4ed1a (= 62dd3b8): `TOOLCHAIN_INSTANCES` with four rows; enumerated at step4.rs:620-640 inside `rank_lint` (step4.rs:533).
- crates/rk-kernel/src/select/lints.rs:362: `load_lints` calls `rank_lint`, so it is a load-time rule (AC-047).
- crates/rk-kernel/src/rigor.rs:561-566: the same four; `rigor_monotonicity_rule` has no caller outside tests (tests/it/rigor.rs, tests/it/review.rs).
- crates/rk-kernel/src/lattice.rs (`Axes::shipped()`) adds a rust row; runbook/phase-1/s8b-catalog-quality.md:679 says only the `.redkiln/` tests use it.
- No record in s8j, s8-exit-criterion, PROGRESS or DECISIONS owns widening the two sweeps.

## Impact
The Phase-1 self-hosting lane is rust. A `.redkiln/` edit that ties two rust-context producers on `method_rank` loads cleanly and fails at run time (`LoadError::RankTie`) or selects arbitrarily.

## Suggested fix
Derive the domain from one shared source: either `lattice::Axes::shipped()` or the registry's `toolchain` facet values. Use it in `rank_lint` and the rigor sweep, and add a fixture with a rust-only tie that must be red.
