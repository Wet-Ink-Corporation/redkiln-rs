TITLE: Make Digest deserialisation validate through from_hex
LABELS: bug
STATUS: untracked

## Finding
`Digest` derives `Deserialize` with `#[serde(transparent)]` over a `String`, so any string deserialises into a `Digest` without the 64-lowercase-hex check. The type's doc calls `from_hex` "the only constructor".

## Evidence
- crates/rk-types/src/digest.rs:19-23 @ ce4ed1a: `#[derive(..., Serialize, Deserialize, schemars::JsonSchema)] #[serde(transparent)] pub struct Digest(String);`
- crates/rk-types/src/digest.rs:35-36 @ ce4ed1a: `/// The only constructor: 64 lowercase hex characters` on `from_hex`.
- runbook/phase-1/s8j-run-preparation.md:902 @ ce4ed1a mentions the bypass only as a bug-hunt candidate EXCLUDED by that slice's method (digests are deserialised on the run and replay paths, which fails rule 1). It schedules and owns no fix.
- Unchanged at 62dd3b8.

## Impact
A malformed digest in a stored payload, sidecar or replayed run record is accepted silently and later compared or used as a key, so a corrupt or hand-edited record fails late (or never) instead of at the read boundary. Code elsewhere assumes the invariant holds.

## Suggested fix
Replace the derived `Deserialize` with `#[serde(try_from = "String")]` backed by a `TryFrom<String>` that calls `from_hex` and maps `DigestError` to a serde error; keep `Serialize` output byte-identical. Tests: valid 64-hex round-trips; 63 chars, uppercase and non-hex fail to deserialise; existing fixtures still load. Confirm the schemars output is unchanged (or add a `pattern`).
