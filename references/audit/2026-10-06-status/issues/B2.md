TITLE: Implement Display for rk-git GitError so operator errors are readable
LABELS: bug
STATUS: untracked

## Finding
`GitError` derives only `Debug` and has no `Display`, so operator-facing git failures are printed with `{e:?}`, which renders `stderr` as a `Vec<u8>` of integers. rk-cli worked around it in several places and left comments saying a `Display` is someone else's job.

## Evidence
- crates/rk-git/src/error.rs:15-16,33,52 @ ce4ed1a: `#[derive(Debug, Clone, PartialEq, Eq)] pub enum GitError`; `NonZeroExit.stderr` and `WorktreeRemoveFailed.stderr` are `Vec<u8>`.
- crates/rk-cli/src/verbs/doctor.rs:114-117 @ ce4ed1a: `eprintln!("redkiln: reconcile at entry refused: {e:?}")`, with a comment that GitError implements no Display.
- crates/rk-cli/src/repo.rs:47-52 @ ce4ed1a: `RepoError` carries the Debug rendering; the doc says a Display is "a job for whoever gives GitError a Display" and would edit a closed crate (7d.15).
- crates/rk-cli/src/doctor/rebuild.rs:143 @ ce4ed1a: same workaround; verbs/run.rs:4788,4946 hand-match only the refusal arms.
- No record at ce4ed1a (runbook/, spikes/DECISIONS-*.md, references/adr) schedules the fix. Unchanged at 62dd3b8 (error.rs has no Display).

## Impact
A failing git call (missing git, locked index, failed worktree remove) shows stderr as `[102, 97, 116, ...]`, so the operator cannot read the cause on the exit-3 paths. Low risk, real annoyance.

## Suggested fix
Add `impl std::fmt::Display for GitError` that prints the op, exit code and `String::from_utf8_lossy(stderr)` truncated to a bound; keep `Debug` unchanged. Switch the `{e:?}` sites in doctor.rs, repo.rs and rebuild.rs to `{e}`. Test: a NonZeroExit with known stderr renders the text, not integers. rk-git is a closed crate, so this needs a dated amendment to the Step 6 closure.
