TITLE: Wire selection step 7 and pack capability routing; add a cross-model test
LABELS: enhancement
STATUS: untracked

## Finding
Step 7 (`step7`, deviation) is called only from the replay harness when a recorded input carries a deviation; no run-path code produces one. AC-494's resolver and AC-495's pack validation have no caller outside their own modules and tests. The crate also holds three independent enumerations of the selection lattice (`select`, `lattice`, `rigor`), and no test compares their results.

## Evidence
- crates/rk-kernel/src/select/step7.rs:344 `step7` @ ce4ed1a: callers are replay.rs:1518 and :2017 only. rk-cli reads recorded runs (verbs/explain.rs:126) but never calls `replay::record`.
- crates/rk-kernel/src/runtime/step.rs:2242: `on_false = { to = "deviate" }` is refused by name as "OWED".
- crates/rk-kernel/src/pack_validation.rs:309 `pack_capability_routing_rule` and resolver.rs:371/:403 `resolve_activity`/`dispatch_if_resolved`: no src caller. lib.rs:230-240 calls these halves ARMED and the capability-need routing record OWED.
- lattice.rs, rigor.rs and select.rs each enumerate contexts. Lattice parity (tests/it/lattice.rs) is against the Python goldens, not against `select`. I found no test comparing results across the three; this is a negative search, not a proof.
- Records: D21-48 X7 (spikes/DECISIONS-2026-09-21.md:1983) accepts the refusal of the deviate route. No record schedules the pack-routing wiring or a cross-model test.

## Impact
AC-061 to AC-064 and AC-494/AC-495 are not exercised on a real run, and the three models can drift (see A3 for the toolchain domain). Not on the M5 path.

## Suggested fix
Add one differential test: for each cell of `lattice::run` over `.redkiln/`, run `select` and compare the selected activity ids. Call `pack_capability_routing_rule` from the run composition root against the adapter's claimed set. If mid-walk deviation stays out of Phase 1, record that in an ADR note.
