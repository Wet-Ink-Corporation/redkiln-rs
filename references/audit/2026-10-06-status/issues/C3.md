TITLE: Define a recovery and re-freeze procedure for a failed first real lane run
LABELS: enhancement, documentation
STATUS: untracked

## Finding
No record says what to do when the first real lane run fails. Checkpoint 8j is one-shot and refuses an existing rk-run/<fix item>, so each repair means a full re-freeze with no documented path.

## Evidence
- runbook/phase-1/s8j-run-preparation.md:2073-2076 @ ce4ed1a: "Checkpoint 8j is one-shot ... never re-run after that launch: (3) refuses an existing rk-run/<fix item> ... (12) refuses a moved store ... A re-run after the first launch fails at (3) by design." Also :184 (review finding 24) and :2191 (FAIL if the rk-run ref exists).
- git grep at ce4ed1a for re-freeze, recovery and abandon in s8j, s8-exit-criterion.md and halts.md finds no procedure.
- Appendix §14: both earlier structural insertions came from first real contact, and two real-path gaps (human roots, hold) are already known, so a failed first run is likely.

## Impact
A failed paid run leaves the operator without a sanctioned route: re-minting the item, resetting rk-run refs, or re-passing 8j are all undefined. There is a risk of improvised, unrecorded state edits.

## Suggested action
Options: (a) write a "failed first run" section: archive the rk-run/<item> ref and store, mint a fresh item (8j.5 already mints one), and re-run 8j (3)/(12) against it; (b) let (3)/(12) accept a recorded abandonment ledger entry; (c) add a time-boxed single real dispatch on the fixture item before the freeze (appendix §14). Recommend (a) plus (c).
