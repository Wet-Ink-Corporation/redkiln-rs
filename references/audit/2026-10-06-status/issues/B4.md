TITLE: Restrict trailer parsing to the commit's final trailer paragraph
LABELS: bug
STATUS: untracked

## Finding
`rk_git::trailer::grammar::parse_body` treats every column-0 `key: value` line anywhere in a commit body as a trailer. Git's trailer block is only the final paragraph, so prose lines such as a quoted `Story: ...` or a `Note: ...` mid-body are classified as trailers (or as UnknownKey/Malformed).

## Evidence
- crates/rk-git/src/trailer/grammar.rs:229-247 @ ce4ed1a: `for line in body.lines() { let Some((key_raw, value_raw)) = line.split_once(": ") ... out.push(classify(key, value)) }`; no paragraph or end-of-message check. The doc at :225-228 says it returns "every line that looks like a trailer".
- references/adr/0188-the-landed-commit-is-a-kernel-made-content-checkpoint-on-the-run-ref.md:175 @ ce4ed1a describes trailer form as `Key: value` at the message's end; ADR-0155 clause 3 describes column 0, ": " and case as the only gates. The parser enforces no position or paragraph rule.
- runbook/phase-1/s8e-tier-one-and-the-lane.md:1746-1750 @ ce4ed1a notes the subject never reaches `parse_body` in production; it does not address mid-body lines.
- Unchanged at 62dd3b8. No record schedules or accepts this.

## Impact
A body paragraph that quotes `Story: x` or `Gate: ...` can mint a phantom signal that reconcile counts, or a spurious Malformed drift row. Redkiln writes its own trailers through `interpret-trailers`, so the exposure is hand-written or pasted commit text, but tier-1 state is derived from this parser.

## Suggested fix
Parse only the last paragraph, and only when every line in it is trailer-shaped or a continuation (matching `git interpret-trailers --parse`), or call `git interpret-trailers --parse` through the existing wrapper. Keep AC-165's surfacing of malformed lines inside that block. Tests: a trailer-like line mid-body is ignored; the same line in the final paragraph is read; a message with no trailer paragraph yields none.
