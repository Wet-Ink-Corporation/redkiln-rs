TITLE: Compute stage per item in `redkiln status` using Event::item()
LABELS: bug
STATUS: untracked

## Finding
`status` takes the `to` of the last `stage_transition` in the whole journal and uses it as the stage for every item. It partitions rows with a local `item_of` that reads `payload["item"]`, not the interim `Event::item()` key (ADR-0182), and folds every item-less row into every item.

## Evidence
- crates/rk-cli/src/verbs/status.rs:172-177 @ ce4ed1a (= 62dd3b8): `item_of` reads `event.payload.get("item")`.
- status.rs:183-191: `recorded_stage` = last `StageTransition` globally.
- status.rs:196-216: `roll_up` hands the one stage and all item-less rows to every item.
- crates/rk-types/src/event.rs:99: `Event::item()` exists; the sibling verbs use it (verbs/explain.rs:225, verbs/cost.rs:378, doctor/rebuild.rs:358).
- Records: status.rs:30-42 carries a "RAISED, not settled" note and ADR-0131 (:35, :108) says the selector would close it. ADR-0182:195-196 owes a whole-store selector "with exclusion", with no stage assigned. Nothing schedules the per-item stage fix.

## Impact
With more than one item in the store, `status` shows the wrong stage and over-reports transitions and gates. No exit check calls `status`, so the cost is operator observability.

## Suggested fix
Partition by `Event::item()`. Derive each item's stage from its own keyed `stage_transition` rows. Treat item-less rows as shared only where ADR-0182 classifies the kind as `Carried`. Extend `lane_e2e::two_items_in_one_store_do_not_fold_together` to cover `status` stage output.
