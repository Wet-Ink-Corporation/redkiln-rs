TITLE: Land the POSIX rk-containment kill fix locally and make is_empty zombie-aware
LABELS: bug
STATUS: untracked

## Finding
On the local branch the POSIX `Group::kill` returns right after `killpg`, before members have died, and `pids` lists zombies, so a caller's first read can see a live tree. Commit 9959b2f fixes this (kill waits for members; zombies read dead) but exists only on origin/build/phase-0-to-1. Even there, `Group::is_empty` still counts zombies.

## Evidence
- crates/rk-containment/src/posix.rs:55-58,72-92 @ ce4ed1a (and 36dd8ac): `kill` is `killpg_all` then `record_kill` then `Ok(())`; `pids` doc: "A zombie is listed until reaped".
- crates/rk-containment/src/posix.rs:71-93 @ 62dd3b8: fixed `kill` polls `pids()` (zombie-filtered) for KILL_WAIT_TICKS; posix.rs:205-220 `is_alive` excludes zombies.
- crates/rk-containment/src/posix.rs:96-100 and ffi.rs:652-665 @ 62dd3b8 (identical at ce4ed1a): `Group::is_empty` calls `group_has_members`, i.e. `kill(-pgid, 0)`, which succeeds for a zombie. The doc at ffi.rs:680-681 admits the same for `is_alive`'s syscall half. `Group::is_empty` has no production caller; its only user is the public API.
- Records: runbook/phase-1/s7c-adapters.md:3120 arms AC-224's POSIX arm to "a recorded CI ubuntu-latest run", but no record at ce4ed1a mentions 9959b2f, the CI failure, or the zombie defect. `git log ce4ed1a..62dd3b8` shows 15 remote commits (CI fixes) the local branch lacks.

## Impact
On POSIX, `run_bounded` timeouts and cancels can report a still-dying tree as alive (flaky `run_bounded_kills_tree_at_timeout`), and AC-224/AC-278 POSIX arms are unreliable. It is on the CI path (D21-42 14a). `is_empty` is a smaller residual: a zombie keeps the group "non-empty".

## Suggested fix
Merge or cherry-pick 9959b2f (and the other CI fixes) into the local branch. Then make `Group::is_empty` return `Ok(self.pids()?.is_empty())` (zombie-filtered `/proc` read), or document it as "includes zombies" and rename it. Add a test with an unreaped exited member. Record the ci.yml-ran-and-was-red fact in PROGRESS.md.
