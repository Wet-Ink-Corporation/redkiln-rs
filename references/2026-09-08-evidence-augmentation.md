# Redkiln-RS — what current published sources say about the corpus

**Date:** 2026-09-08 · **Status:** External-research pass. Checks the spike corpus and `2026-09-07-design-recommendation.md` against sources live as of today; changes nothing on its own authority. · **Method:** nine independent research agents, one per axis (Rust practice · dependencies · orchestration · durable execution · context/caching · method engineering · verification · competitors · decision records), each returning typed `confirms` / `contradicts` / `adds` / `unresolved`. · **Inputs:** 48 confirmations, 13 contradictions, 44 new findings, 30 unresolved items. · **Evidence discipline:** every claim carries a source tag — [peer] / [preprint] / [1P] first-party / [vendor] / [blog] / [Pr] practitioner. Numbers are quoted as the agent read them; nothing is rounded. Where a claim rests on one source, or where an agent could not fetch the primary, the row says UNVERIFIED. **Nine agents finding nothing against a claim means "no current source contradicts it", not "confirmed".**

**Errata (2026-09-11):** this pass is a dated record. Where the pre-implementation audit of 2026-09-10 (`references/audit/2026-09-10/MASTER.json`, PIA-001…PIA-110) and its citation census found a row wrong, the row stands as written and a `**Erratum (2026-09-11, PIA-0NN).**` row or paragraph sits directly beneath it, citing `references/adr/ERRATA.md` ids (E-NNNN-k) where an accepted record carries the same correction. Every fetch behind an erratum is dated 2026-09-10 unless stated; every research read going forward carries a fetch date.

## 4. Recommendations for the design

Numbered, each naming the design element it touches.

1. **D16, card delivery — set both TTL variables, not one.** Add `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL=1h` alongside `CLAUDE_CODE_PROMPT_CACHE_TTL=1h`, and verify per run from `usage.cache_creation.ephemeral_1h_input_tokens` vs `ephemeral_5m_input_tokens` rather than assuming either took. Record billing mode (plan-included vs usage credits) as a confound on every cache measurement, since usage-credit billing silently forces 5m even on an explicit 1h subagent request. [1P] code.claude.com prompt-caching.
2. **§4 cache model — re-scope the sentence.** Replace "the cache is org-scoped" with "workspace-scoped on the Claude API / AWS / Foundry, org-scoped only on Bedrock and GCP, and additionally scoped to machine + directory + git-status inside Claude Code." The F28 subsidy is real within that narrower boundary; its reach was overstated. [1P] platform.claude.com + code.claude.com prompt-caching.
3. **Phase 1 `rk-git` — spike the common-dir scenario before committing.** gitoxide's own status doc says the `GIT_COMMON_DIR`/`GIT_WORK_TREE` interplay is not implemented. Make it a go/no-go gate; plan the hybrid (gix for rev-parse, status, shallow clone by SHA, trailer parsing; shell out for `git worktree add/remove`). [1P] GitoxideLabs/gitoxide crate-status.md.
4. **Tier-1 state (git trailers) — verify or shell out for trailer writing.** Confirm a concrete write API in the pinned gix version with a unit test, or route the write path through `git interpret-trailers --in-place` / `git commit --trailer`. [1P] gitoxide crate-status.md.
5. **New ADR — async port dispatch.** Record explicitly whether ports use `async-trait` (boxed future per call) or are sync with `.await` confined to adapters. Native async-fn-in-trait does not give a dyn-compatible port. This touches D3's five ports directly. [1P] async-fundamentals-initiative.
6. **Dependency policy — pin `gix = "=0.87.1"` exactly and wire `cargo audit` into CI now**, watching `gix-*` specifically. The advisory history is dense and concentrated in checkout/path handling on Windows — the disposable-worktree surface. Treat gix version currency as a release-blocking check. [1P] RustSec / GitHub Advisory Database.
7. **Schema discipline — add a golden-schema snapshot test** (insta) asserting generated schemars output carries no `oneOf`, sets `additionalProperties: false`, orders required-first, and respects the ≤24-optional / ≤16-union caps. schemars emits `oneOf` for data-carrying enum variants by default; §4.4's rule is a constraint on the Rust types, not a schemars guarantee. [1P] docs.rs/schemars.
8. **Repo hygiene, in severity order:** stand up a minimal CI workflow (`cargo fmt --check`, `cargo clippy --workspace --all-targets`, `cargo test --workspace`) — there is none; add a root `rust-toolchain.toml` pinning the exact rustc version, since the product is a binary not a published library; add `[workspace.lints.*]` with `clippy::all` denied, a curated pedantic subset at deny, and nursery at warn only. [1P] Cargo Book Lints, Clippy Lints book, RFC 3537.
9. **Claim 2 (durable execution) — re-argue, don't re-assert.** Drop "temporal-sdk-core is a 2021 alpha placeholder" and "graph-flow hard-depends on sqlx+postgres"; both are false. Keep the conclusion on facts that hold: Temporal's Rust SDK still mandates a server; graph-flow's in-memory mode is not durable and its postgres feature reintroduces the dependency; `iopsystems/durable` requires Postgres plus WASM-component compilation. [1P] crates.io / GitHub.
10. **D17, gate record — add an explicit staleness re-validation rule at the read site**, and pick one expiry style deliberately (error, as AWS/DBOS, or sentinel the caller branches on, as Inngest). No surveyed platform invalidates a stale-but-unexpired token automatically; the tree-hash binding is what makes redkiln's gate stronger, and the doc should say why. [1P] Restate / DBOS / Step Functions / Inngest / Trigger.dev.
11. **§9 Sources — merge the Jin & Chen entries into one citation.** Currently listed as two; they are one paper, and counting them as two overstates independent replication behind the D4 rebuild. [preprint/peer] arXiv 2603.00539.
12. **D19 — add SWE-Gate as a second, fresher anchor.** 34% of functionally-passing agent repairs fail review constraints derived from real PR comments. It is more directly on-topic for "green tests ≠ pinned criterion" than anything currently cited for that specific claim. [preprint] arXiv 2609.04167.
13. **§2 negative controls — add a confirmation-bias fixture.** The design guards against rationale-driven false rejection (Jin & Chen) but not against positively-framed input driving false approval, where detection drops 16–93% and the loss is almost entirely false negatives. The S-SUBTLE fixture family should gain a "presented as already approved" arm. [preprint] arXiv 2603.18740.
14. **§3 cost table — footnote the Cloudflare tier figure** as an average ($1.68) whose median is $1.47, against a pooled median of $0.98. [1P/blog] blog.cloudflare.com.
15. **Claim 2 (competitors) — narrow to "in an AI-coding-specific backlog or spec tool."** Jira shipped a durable named-approver gate on a work item in May 2026 on generic workflow machinery. The differentiation survives the narrowing; the tool-agnostic phrasing does not. [1P] Atlassian.
16. **Claim 8 (orchestration) — drop the "four or more workers" threshold** or mark it an informal industry observation. One vendor post, no benchmark, no model, no window size. [vendor] beam.ai.
17. **Claim 7 (orchestration) — soften "the current production consensus"** to "a growing and increasingly recommended pattern, not yet uniform." Some 2026 material argues for a deterministic core; other material describes the field retreating to narrower deterministic products as a *reaction* rather than a settled starting point. See §5.
18. **Claim 7 (context) — soften "prose adds nothing"** to "usually sufficient for file selection, but drops rationale and caveats," and carry judgment calls as explicit structured fields (`notes`/`caveats`) rather than assuming prose is discardable. Grounded in the vendor's own compaction-loss guidance. [1P] code.claude.com context-window.
19. **Decision-record docs — stop presenting ADR immutability as an industry standard.** State it as redkiln's chosen convention matching `adr-tools -s`; MADR itself permits in-place status transitions. The `validate --kb` immutability rule stays — it just isn't inherited. [1P] github.com/adr/madr.
20. **AC type (§5) — prefer EARS single-trigger phrasing for gate-checked ACs.** Reserve Gherkin for ACs that already have or will have a runnable feature file. This bears on whether `gwt: Option<Gwt>` is the right default shape for criteria a lint must parse. [peer] Mavin et al. IEEE RE'09.
21. **P1 write-up — cite the external corroboration and skip the temperature spike.** arXiv 2603.04417 and 2604.22411 reproduce the phenomenon across five 2026 frontier models including the Claude family, and measure Claude-Sonnet-4 at background temperature 0 — so P1's instability is very likely schema-induced. Instead, apply arXiv 2511.01176's boundary-distance diagnostic to the existing draws. [preprint] ×3.
22. **Closed-policy risk (rigor enum, `applicable_if`) — cite the Dagster RFC.** First-party, dated, live, and verbatim on the failure shape: a small enum that could not compose, replaced by composable primitives. [1P] dagster-io/dagster #22811.
23. **Rank-reversal justification — cite the general MCDM result**, not only an AHP source, so "just use TOPSIS" is pre-answered. [peer] ScienceDirect S0895717711007850.
24. **P8 additions:** log the `/rewind` vs `/compact` cost asymmetry after an idle gate; record the 5-second fan-out stagger as a dispatch-timing confound; and treat per-worktree cold cache as structural rather than a rig defect. [1P] code.claude.com prompt-caching.
