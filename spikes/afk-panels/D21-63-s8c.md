# D21-63 panel ruling (s8c, blocker E), full text — TAKEN PROVISIONALLY 2026-09-26 under the AFK rule

## Judges

- **Judge 1** recommended: (1) as the provisional ruling now: keep cvss-unscorable and add one sentence to proposed record V. It moves no accepted Decision, V lists in-tree code as its sanctioned alternative, and it is the most reversible option. Option (3) should be ruled on before s8g §8g.6 runs sca-scan over the real database, because V already names the `cvss` crate and a refusal cannot satisfy N25's pass-or-gate routing.
  - new option: A hybrid of (3) and (1), for the durable ruling before s8g. Swap in the `cvss` 2.2.0 crate (default features include v4; the only dependency is serde, which is optional) to score v3.0, v3.1 and v4.0 vectors on V's existing numeric bands, since v4.0's qualitative scale uses the same boundaries. Keep the cvss-unscorable refusal by name for any vector the crate cannot parse (malformed, or an unknown version). V gains one sentence covering both points plus the `cargo deny check licenses` reading it already requires. No vector is ever counted unrated. Every matched advisory in today's database (v3.0, v3.1, v4.0) gets a band, so N25's pass-or-gate routing holds over the real database.

- **Judge 2** recommended: (1) Keep the fail-closed refusal. Record V decision 5 gains one sentence: a matched advisory whose vector the named scorer cannot score (a CVSS v4.0 vector, or a malformed one) refuses the scan by name (`cvss-unscorable`, naming the vector). It is never counted `unrated` and never banded by a guess. Register it as a provisional D21-62-style ruling. Options 2 and 3 are each one clause and one code branch away, and s8g §8g.6's sca-scan should name the refusal as a known halt.
  - new option: Option 1 plus a small addition. - **Judge 3** recommended: A variant of option (3), listed under new_option: score v4.0 vectors with the cvss crate pinned =2.2.0 (the version rustsec 0.33 parses the database with), band them on V's existing bands, and KEEP the built cvss-unscorable refusal for any vector the crate rejects. If the panel weights the AFK rule's most-reversible preference over this lens, option (1) is an acceptable interim: nothing is matched today (0 vulnerabilities on the current lockfile), but it has to be replaced before s8g's scan runs over the real database.
  - new option: (3') Fail-closed option (3), one code branch. Add `cvss = { version = \"=2.2.0\", default-features = false, features = [\"std\", \"v3\", \"v4\"] }` to rk-adapter-toolchain-rust. In `severity_of`, send a `CVSS:4.0/` vector to `cvss::v4::Vector::from_str(..).score().value()` and band it on V's existing thresholds, 0.0 counting as low as V already says. Keep `cvss-unscorable` for any vector the crate rejects, so a malformed vector still refuses by name and is never counted unrated. Pinning with `=` to the version rustsec 0.33 uses means the adapter's scorer is the same parser that accepted the database the tools loaded. Red-first: a fixture advisory with the crate's own CVE-2025-47273 v4.0 vector must band `high` (7.7). Today that fixture refuses with cvss-unscorable, so the test is red now. Also add one v4.0 vector that scores 0.0 and must count low, and a differential test that pins the in-tree v3 scorer against `cvss::v3` over a copied fixture of v3 vectors, so the two scorers cannot drift apart silently. Record V gains two sentences: v4.0 base scores use the same qualitative bands (FIRST v4.0 §6), and a vector the named scorer rejects refuses by name. Reversal is one dependency line plus one match arm; it moves no accepted ADR's Decision, because V is still proposed and already names this crate. Also measure `cargo deny check licenses` and `cargo deny check bans` after adding the dependency, as V decision 5 requires ('if the crate, the `cargo deny check licenses` reading over it and its transitive dependencies').

## Blocker

CVSS v4.0 vectors: record V (ADR-0170, proposed) does not settle how a matched advisory with a v4.0 or unscorable vector is banded.

## Ruling

Take option (1) provisionally, as already built at 5561afa, with two additions. Record (3') as the preferred durable remedy but do not build it now.

1. Code: no change to behaviour. `verbs::severity_of` in crates/rk-adapter-toolchain-rust/src/verbs.rs keeps scoring CVSS:3.0 and CVSS:3.1 vectors with the in-tree v3.1 base equations. When a MATCHED advisory's vector is CVSS:4.0, malformed, or any other version, it keeps refusing the whole sca-scan by name: `refuse("sca_scan", "cvss-unscorable", "`<vector>`: <detail>")`. Such an advisory is never counted `unrated`, never banded by a guess, and never dropped. Only advisories that match the lockfile are scored, as today.

2. Refusal text (addition): the cvss-unscorable detail string must also name its two remedies, so an AFK halt is one operator decision away: "score it with the RustSec `cvss` crate's v4 scorer (record V decision 5), or rule it `unrated` so sca-scan routes to scan.accept-findings". This is text only. It changes no ScanReport field, no dependency, no Cargo.lock and no deny.toml.

3. Tests, red-first, if P5 has not already landed them:
   - (a) A matched fixture advisory carrying a CVSS:4.0 vector (use `cvss` 2.2.0's own CVE-2025-47273 vector) makes sca-scan refuse `cvss-unscorable`. The refusal names that vector, and no ScanReport is emitted.
   - (b) A malformed vector refuses the same way.
   - Named mutant: replace the `map_err(... cvss-unscorable ...)` branch with `Ok(None)` (count as unrated). Test (a) must kill it, so option (2) cannot land silently.

4. Record V (ADR-0170, status proposed; this is an edit to a proposed record, not a supersession). Decision 5 "Severity" gains one sentence after "The builder records which landed ...": "In-tree CVSS v3.1 base-score code landed (v3.0 vectors scored by the same equations). A matched advisory whose vector that scorer cannot score (a CVSS v4.0 vector, or a malformed one) refuses the scan by name (`cvss-unscorable`, naming the vector); it is never counted `unrated`, since it has a CVSS, and never banded by a guess. Provisional under D21-<next>; the named alternative is the `cvss` crate's v4 scorer banded on these same bands (FIRST CVSS v4.0 §6 uses the v3 qualitative scale), which reverses this clause as one dependency line and one match arm." "What this forbids" gains: "Counting an advisory whose vector could not be scored as `unrated`, or banding it by a guess."

5. Ledger: register the next free D21 entry after D21-62 in spikes/DECISIONS-2026-09-21.md as TAKEN PROVISIONALLY under the AFK rule, and put the panel text in spikes/afk-panels/. It should state the ruling, the reversal path, and (3') as the operator's preferred durable choice.

6. Downstream precondition, which is the key constraint: before s8g §8g.6 runs sca-scan over the real (non-fixture) advisory database, s8g's open must run `cargo audit --json --no-fetch --file Cargo.lock` and list every MATCHED advisory's vector version. If any matched vector is not CVSS:3.x, s8g stops with a named, expected halt ("sca-scan would refuse cvss-unscorable"), not an unforeseen blocker, and (3') is ruled then. Measured on 2026-09-26 at 5561afa's tree: vulnerabilities = [] (one 'unsound' warning), so no vector reaches the scorer today.

(3') spec, for when it is taken:
- Add `cvss = { version = "=2.2.0", default-features = false, features = ["std","v3","v4"] }` to rk-adapter-toolchain-rust.
- Route `CVSS:4.0/` vectors to `cvss::v4::Vector::from_str(..)?.score().value()`, banded on V's existing thresholds (0.0 counts low).
- Keep cvss-unscorable for anything the crate rejects.
- Add a red-first fixture: CVE-2025-47273's v4 vector must band high (7.7). Add a v4 vector scoring 0.0 that must count low.
- Add a differential test pinning the in-tree v3 scorer against `cvss::v3` over a copied fixture of v3 vectors.
- Take `cargo deny check licenses` and `cargo deny check bans` readings, which V decision 5 requires.

**Why.** Weighting of the three judges:
- Records lens: (1)=8, (2)=3, (3)=8.
- Reversibility lens: (1)=9, (2)=6, (3)=5.
- Engineering lens: (1)=7, (2)=3, (3')=8.5.
- Totals: (1) 24, (3) about 21.5, (2) 12.

The records lens holds no veto against (1) or (3). Record V is proposed, and it names both in-tree code and the `cvss` crate as sanctioned scorers ("The alternative is in-tree CVSS v3.1 base-score code. The builder records which landed"). All three judges reject (2). V says "**An advisory with no CVSS is counted in `unrated`**", and it keeps a scored 0.0 out of unrated "because it was scored". A v4.0 advisory has a CVSS, so calling it unrated would reword a Decision sentence, not extend it. It would also give the operator's gate a possibly-critical advisory under the wrong label, and merge scorer bugs into a human gate (the silent-default pattern ADR-0140 names).

Between (1) and (3), the AFK rule prefers the most reversible, and V's own driver says "Every D21-62 ruling is provisional, so its clause here must be undoable as one clause and one code branch." Option (1) is already built. It touches no Cargo.lock, deny.toml or ScanReport field, and it fails closed by name like V's other refusals. Both (2) and (3) remain one branch away from it. Nothing is blocked today: the measured audit over the current lockfile shows zero matched advisories, and neither fixture advisory is v4.0.

The engineering lens's point is real and is carried into the ruling. 63 of 431 database vectors (about 15%) are v4.0, and the crate scored all 63 with 0 failures. It is the same parser rustsec 0.33 uses to load the database. A refusal does not satisfy D21-43 N25's pass-or-gate routing ("`sca-scan` requires `unrated == 0` or goes to `scan.accept-findings`"). So (1) is sound only as the interim. Hence the named s8g precondition and the remedy-naming refusal text: a later matched v4.0 advisory becomes an expected, one-decision stop, not a silent pass or an unforeseen blocker.

**Reversibility.** Very high. The ruling is the code already at 5561afa plus refusal text, tests, and record and ledger sentences.

Moving to (3') means adding one dependency line and one match arm in front of the refusal branch in `severity_of`, with a Cargo.lock change and deny readings. No ScanReport schema change, and no rows need re-banding, because no v4.0 advisory has ever been scored or counted.

Moving to (2) means changing the refusal branch to `Ok(None)`. The named mutant test would have to be inverted, and V's "no CVSS" sentence reworded, which is why it is disfavoured.

Record V is proposed, so its sentence is edited in place.

**Moves an accepted ADR?** None. ADR-0170 (record V) is status proposed, and the ruling adds one sentence to its Decision 5 plus one forbids line, inside the options V already sanctions (in-tree scorer, or the `cvss` crate). No accepted ADR's Decision is moved, so no superseding record is needed. D21-42 6a ("unrated advisories are never counted as 0") and D21-43 N25 are untouched: nothing is counted as 0, and unrated keeps its meaning. N25's pass-or-gate routing is guarded by the s8g precondition, not amended. The provisional ruling is carried by the next D21 ledger entry after D21-62 and by record V's added sentence.
